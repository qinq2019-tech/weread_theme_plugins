# 微信读书 · 书房（WeRead Studio）

给微信读书网页版（`weread.qq.com`）加一张自己的书桌：主题化界面、继续阅读、每日目标、摘录收藏（可编辑 / 按书归档 / 导出 Markdown）、阅读器色温与沉浸，以及每套主题自己的专属内容区。

Manifest V3，Chrome / Edge 共用同一份代码。所有数据只写在本机扩展存储里，不联网、不碰账号凭据。

> 想接手开发 / 换设备继续？先看 **`PROJECT-STATUS.md`**——项目进展、当前卡点、验证命令、接手步骤都在那一份里。

---

## 一、装了以后会看到什么

**首页**：内容区最上方一条「我的书桌」——问候、继续阅读卡片、今日目标环、最近一句摘录。书桌下方是**主题专属区**，换主题时整条换形状：

| 主题 | 专属区 | 内容 |
|---|---|---|
| 私人书房 | 摘句墙 | 便笺叠 + 三枚竖排纸书签 |
| 书架画廊 | 墙上的书 | 一排等高不等宽的书脊 + 最近在读题签 |
| 轻彩空间 | 读过的日子 | 35 天点阵日历 + 本周 / 连着 / 最早 |

**右下角**：一个 44px 圆钮，展开后能换主题、明暗、字体、留白，写摘录（到 200 条上限会当场告知），阅读器上还能调护眼色温和沉浸模式，以及一键「恢复原版」。

**阅读器**：暖色温层（不碰正文排版）、可选的顶底栏隐藏、把当前书名/章节记到本机。

**设置页**：三套主题预览、各模块开关、每日目标、**摘录管理**（按书 / 按时间两个视图、就地编辑、删除 8 秒内可撤销、导出 Markdown）、数据导出/导入/清空。

## 二、安装

### Chrome

1. 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（`weread-studio`）
4. 打开 <https://weread.qq.com/>，右下角出现圆钮即成功

### Edge

1. 打开 `edge://extensions/`
2. 左下角打开「开发人员模式」
3. 点「加载解压缩的扩展」，选择本目录
4. 其余同上

> Edge 与 Chrome 的扩展 API 兼容，但仍需在 Edge 上实测一遍——见第六节验收清单。

## 四、为什么是这个架构

| 决策 | 原因 |
|---|---|
| **纯内容脚本为主，不用 background 常驻** | 视觉增强 + 局部组件，不需要跨标签页拦截。只有「阅读时长跨标签聚合」需要 SW，就只把这一件事放进去。 |
| **Shadow DOM 承载所有新增 UI** | 站点是 Nuxt/Vue，全局样式与哈希类名很容易污染注入内容；隔离后我们的视觉不受站点改版影响，也不反过来污染站点。 |
| **站点样式集中在一个适配层文件** | 线上首页用不带哈希的语义类（`.home_page_container` / `.ranking_block_*`），书架与阅读器靠 `body.wr_page_shelf` / `body.wr_page_reader` 区分。所有选择器只写在 `10-adapter.js`，改版只改这一个文件，其它模块零改动。 |
| **封面匹配不依赖类名** | 从封面节点向上找两层，只要这段文本里含书名就认为命中。站点换类名也不影响「继续阅读」的配图。 |
| **主题只写 CSS 变量，不逐条覆盖站点元素** | 站点优先级高，逐条覆盖要写一堆 `!important` 且脆弱；变量配合少量页面规则更稳、更好撤。 |
| **页面底色只在「明暗一致」时覆盖** | 站点深色 + 你选浅色会导致浅字压浅底。所以判出不一致时只改结构与字体，不动底色字色。 |
| **内容脚本之间用全局命名空间 + IIFE** | MV3 的 content script 不支持 ES module；依赖顺序由 manifest 的 `js` 数组保证。 |
| **SW 不留全局变量** | MV3 的 service worker 会空闲被回收；「上次上报时间」放 `storage.session`，累计值放 `storage.local`。 |
| **时长由 SW 按 tabId 去重累加** | 同一本书开两个标签页时，各自累加会重复计时。 |

## 五、怎么改

**换颜色/加主题**：改 `src/shared/palette.js`。每个主题有 `light` / `dark` 两套令牌，设置页的色卡会自动跟着变。

**改书桌内容**：`30-desk.js` 的 `buildDesktop()`。模块开关在 `deskModules`。

**站点改版导致某块失效**：只需要动 `10-adapter.js` 的 `CANDIDATES`。先用弹窗的「页面适配诊断」看哪一项变成「未匹配」。

**加新功能**：新建一个 `src/content/XX-xxx.js`，在 manifest 的 `js` 数组里排在 `60-boot.js` 之前，用 `RK.bus` 收发事件即可，不用改旧代码。

## 六、验收清单（装完自己跑一遍）

| 检查项 | 预期 |
|---|---|
| 首页右下角出现圆钮 | 出现；点开能换主题并即时生效 |
| 首页顶部出现「我的书桌」 | 有问候、日期、目标环；没读过书时继续阅读显示为空态提示 |
| 书桌下方出现主题专属区 | paper=摘句墙、gallery=书脊墙、pastel=日历；切主题整条换形状；关闭对应开关后不留空隙 |
| 打开一本书，读几秒回首页 | 「继续阅读」出现刚才那本书和章节；书脊墙 / 题签同步更新 |
| 换主题 + 刷新页面 | 主题保持；页面底色与面板同时变化 |
| 阅读器打护眼色温 40 | 页面整体偏暖；调到 0 完全恢复 |
| 打开「沉浸阅读」 | 顶底栏消失，右下角圆钮仍在，可随时关掉 |
| 功能坞写摘录 → 管理摘录 | 跳到设置页并定位到摘录卡片 |
| 设置页摘录：改一条 | 就地编辑，Esc 取消、Ctrl/Cmd+Enter 保存，保存后内容与书名落库 |
| 设置页摘录：删一条 | 立即消失，8 秒内可点「撤销」原位恢复；超时不弹任何提示 |
| 导出 Markdown | 下载 `weread-quotes-日期.md`，按书分组、只含真实字段 |
| 关掉总开关 | 页面立刻回到微信读书原样，不留残余样式 |
| 卸载扩展再装回 | 设置与摘录仍在（`storage.local` 未清）；点「清空数据」后才消失 |
| Edge 上重复以上 | 全部一致；不一致就把「诊断」结果发我 |
| 打开扩展页面控制台 | 无红色报错 |

**诊断入口**：点圆钮 → 更多设置 → 回弹窗点「重新检测适配」，能看到页面类型、内容区是否命中、识别到几个封面、书桌/坞是否挂载、顶底栏候选数、正文是否 canvas。

## 七、它做不到什么 / 合规红线

- **不改登录、搜索、阅读、购买流程**，只加视觉层和自己的一块内容区。
- **不请求微信读书非公开接口**、不绕过付费与会员限制、不批量抓取书籍正文。
- **阅读时长是本机估算**，只统计这台电脑浏览器里的停留时间，不等于账号在手机/其它设备上的官方统计。
- **继续阅读来自本机记录**，不是服务端进度；换设备不会同步。
- **正文排版不强行改**：线上阅读器部分版本把正文画在 canvas 上，改字号/行距会破坏排版，所以只做光学色温层。
- **站点改版会让增强失效**：此时点「恢复原版」，或等适配层更新；不会影响正常读书。
- **数据只在本机**：卸载扩展即删除（导出备份可另存）。

**过程中被实测推翻的两个假设**（已按真实情况改掉）

1. 线上首页已经**不是** Nuxt 版：没有 `#__nuxt`，也没有任何 `.wr_index_page_*`，改用不带哈希的语义类（`home_page_container` / `ranking_block_*`）。早期按旧快照写死的选择器全部失效，适配层已改成「新结构优先 + 旧结构兜底」，并且封面匹配不依赖类名，只按「祖先文本里含书名」找。
2. 阅读器顶栏只有「加入书架 / 首页 / 我的书架 / 登录」，**没有章节名**。最初想从顶栏猜章节，会把「加入书架」写进阅读记录，已改为不猜：只有站点真的提供章节标题元素时才填。

**仍未验证（需要你登录后在真浏览器里确认）**

- **v0.2 的新 UI 在真实微信读书页面上的表现**（专属区挂载、竖排书名的字体回退）——自动化与静态预览都过了，但未在登录后的线上首页实测。
- **设置页摘录管理在真浏览器的手感**（行为测试用 DOM 桩，无法覆盖真实布局与读屏表现）。
- 书架页（`/web/shelf`）是登录后客户端渲染，本次未登录无法验证；当前只保证功能坞能挂上。
- 登录后阅读器进入真实正文 canvas 后的表现（进度百分比、章节记录）。
- Edge 上的行为（API 兼容，但仍需实测一遍）。
- 站点灰度/改版后的结构变化——用弹窗里的「页面适配诊断」看哪一项变成未匹配。
